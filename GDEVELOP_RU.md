# RuStore Pay для GDevelop: импорт и события

## Скачать расширение

[RuStorePay_GDevelop_1.0.0.json — прямая ссылка](https://raw.githubusercontent.com/artemkz147-ship-it/rustorpay147/main/RuStorePay_GDevelop_1.0.0.json)

Скачайте JSON. В менеджере проекта GDevelop откройте раздел расширений,
выберите импорт расширения из файла и укажите скачанный JSON.
После импорта появится расширение **RuStore Pay — покупки для Android** (`RuStorePay`).

Расширение подключает Cordova-плагин 1.0.3 с Pay SDK 11.1.0.
Зависимость закреплена на коммите `5d3cb99ab786cdcf89d6943824b484c22d063c62`.
Для этого приложения используется Console App ID **2063744155**.
Для другого приложения нужно изменить App ID в нативном плагине и закрепить
новый коммит в JSON; изменение только действия инициализации недостаточно.

## Сборка

Для опубликованной игры сохраните прежний Package Name и настройки подписи
автоматической Android-сборки GDevelop. Увеличьте номер версии игры.
Покупки проверяются в установленном Android APK, а не в браузерном предпросмотре.
Возможность установки этой зависимости облачным сборщиком ещё требует проверки.

## Настроить магазин

1. При запуске первой сцены, один раз: действие **Инициализировать RuStore Pay**.
2. При успешном завершении `initialize`: действие **Проверить доступность платежей**.
3. После проверки используйте условие **Платежи доступны**, чтобы разрешить покупку.
4. Действие **Получить товары** принимает строку с JSON-массивом ID товаров.
   Пример строкового выражения GDevelop: `"[\"coins100\",\"premium\"]"`.
5. После успешного `getProducts` выражение `RuStorePay::ResultJSON("getProducts")`
   содержит массив товаров. Преобразуйте JSON в переменную штатным действием
   GDevelop. Поле `amountLabel` содержит цену для отображения игроку.

## Покупка и выдача товара

1. По нажатию кнопки с условием «Выполнить один раз» вызовите **Купить товар**,
   передав ID товара из консоли RuStore. Пока покупка выполняется, отключите кнопку.
2. Дождитесь условия **Операция завершилась успешно** для `purchase`.
   Это результат одностадийной оплаты, которую запускает нативный плагин.
3. Скопируйте `RuStorePay::PurchaseId()`, `RuStorePay::PurchasedProductId()`
   и при необходимости `RuStorePay::InvoiceId()` в переменные игры.
4. Проверьте, не обрабатывали ли уже этот `purchaseId`. Выдайте товар и надёжно
   сохраните изменение вместе с обработанным ID. Расширение не сохраняет награду
   и не обеспечивает защиту от повторной выдачи после перезапуска игры.
5. Затем вызовите **Подтвердить выдачу товара** с сохранённым ID покупки.
   Это отметка `ACKNOWLEDGED`, а не действие списания денег.
6. После обработки результата вызовите **Очистить обработанный результат**.
   Условие успеха остаётся истинным до очистки или следующего запроса;
   используйте «Выполнить один раз», чтобы не выдавать товар каждый кадр.

При ошибке или отмене оплаты награда не выдаётся. Используйте
`RuStorePay::ErrorMessage("purchase")` и `RuStorePay::ErrorCode("purchase")`.
Отмена может иметь код `ProductPurchaseCancelled`.

## Восстановление покупок

Вызовите **Получить покупки пользователя**, затем преобразуйте
`RuStorePay::ResultJSON("getPurchases")` в переменную. Проверяйте состояние оплаты,
тип товара, `acknowledgementState` и сохранённые в игре обработанные ID.
Не выдавайте повторно расходуемые товары только потому, что они есть в списке.
Возврат покупки, которая была оплачена до закрытия игры, должен обрабатываться
теми же правилами сохранения и подтверждения выдачи.

## Имена операций

Эти значения выбираются в условиях состояния и выражениях результатов.

| Действие | Операция |
|---|---|
| Инициализировать RuStore Pay | `initialize` |
| Проверить доступность платежей | `getPurchaseAvailability` |
| Получить статус авторизации | `getUserAuthorizationStatus` |
| Получить товары | `getProducts` |
| Купить товар | `purchase` |
| Получить покупки пользователя | `getPurchases` |
| Получить покупку по ID | `getPurchase` |
| Подтвердить выдачу товара | `acknowledgePurchase` |

Результаты хранятся отдельно для каждой операции и сохраняются при смене сцены
в пределах запущенной игры. Одновременные запросы одного типа не запускаются.
Очистка результата не отменяет выполняющийся запрос.

## Проверка кода

```sh
node scripts/build-extension.cjs
node --test tests/extension.test.cjs
```

Тесты выполняют JavaScript из JSON и реальный JS-мост плагина с имитацией
нативного Cordova-вызова. Они проверяют состояния, ошибки, передачу параметров
и блокировку повторной оплаты. Они не проверяют импорт в редактор GDevelop,
компиляцию Android, подпись APK или реальные платежи RuStore.

После облачной сборки проверьте на телефоне товары, успешную тестовую покупку,
отмену, возврат из банковского приложения и восстановление после перезапуска.
